Because “forward/loss” is really doing a lot more than a plain model forward or the loss arithmetic.

In CF gradient, this call runs with `grad_enabled=True` and a `SeedProjectionInstrument` patcher. That means every hooked `(layer, kind)` does extra SAE work during the forward:

```101:137:src/circuit/instrument/sae_graph.py
    def transform(self, layer_idx: int, kind: str, x: torch.Tensor) -> torch.Tensor:
        # 1. Encode — top_acts is connected to x through the encoder
        top_acts, top_indices = self.bank.encode(x, kind, layer_idx)
        B, T, _ = x.shape
        d_sae = self.bank.d_sae
        target_dtype = x.dtype

        # Construct full sparse feature tensor (needed for joint feature+residual attribution)
        f = sparse_topk_to_dense(top_acts, top_indices, d_sae, dtype=target_dtype)

        # 2. Decode and compute residual
        x_hat_connected = self.bank.decode(f, kind, layer_idx)
        residual = x - x_hat_connected
        // ...
        f_grad = f.detach().requires_grad_(True)
        res_anchor = residual.detach().requires_grad_(True)
        // ...
        reconstruction = self.bank.decode(f_grad, kind, layer_idx)
        return reconstruction + res_anchor + (x - x.detach())
```

So per forward it is:

- running the transformer with gradients enabled
- disabling compile when a patcher is present
- applying hooks/patches at SAE sites
- SAE encode at each hooked point
- expanding sparse top-k activations into dense `d_sae` tensors
- decoding once to compute residual
- creating detached grad anchors
- decoding again from `f_grad`
- storing all anchors/activations in `FeatureGraph`
- keeping the autograd graph alive so attribution can be computed later

So yes, the long bit is not “MSE loss”. It is the instrumented grad-enabled forward needed to make the later single backward attribution possible.

What about the other second in cf grad?

---

The “other second” is mostly split between **probe dataset construction** and **negctx selection**, depending on mode.

Post-warmup worked rows:

- `probe_dataset_s`: mean `0.66s`
- `negctx_selection_s`: mean `0.58s`
- `posctx_activation_s`: mean `0.014s`
- `faithfulness_eval_s`: mean `0.13s`
- misc/assembly/logging: mean `0.02s`

By mode:

- `random`: the extra time is mostly probe dataset, about `0.66s`; negctx is tiny, about `0.067s`.
- `distant`: probe dataset about `0.60s`, negctx about `0.87s`.
- `close`: probe dataset about `0.76s`, negctx about `0.92s`.

So after the instrumented forward, the next biggest costs are:

1. Building/loading the probe dataset for the seed.
2. For `close`/`distant`, ranking/filtering negctx candidates using `seq_repr` plus seed non-activation filtering.
3. Final faithfulness eval is smaller, usually under `0.1s`, except one close row at `0.64s`.

In short: CF grad is now roughly **1.2-1.6s instrumented grad forward**, plus **0.6-0.9s probe/negctx prep**, plus small evaluation overhead.
